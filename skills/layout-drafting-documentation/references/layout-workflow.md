# LayOut: рабочий процесс и границы автоматизации

## Среда и исходники

Установи точную версию/build LayOut и SketchUp, ОС, лицензированный доступ, сохранённые/открытые документы и их состояние. Документация онлайн обновляется; функция описанная в 2026 может отсутствовать в 2025. Не обновляй программу ради оформления без соответствующего задания.

При прямом доступе действуй через доступный подтверждённый API/MCP либо UI. Для SketchUp в этом workspace применяй инструкции `sketchup-local`: сначала status и узкий запрос, единицы mm, именованные операции, без параллельных записей в модель. Не приписывай этому MCP функции LayOut, которых нет в текущей схеме.

В другом навыке могут быть описаны `layout_status/layout_build`: это проектный файловый мост, не универсальный API LayOut. При использовании сначала проверь существование инструмента и его актуальные поля/возможности. Базовая сборка видов не означает автоматические размеры, нормативный штамп или спецификации. API SketchUp и API LayOut — разные среды.

Если мост отсутствует, найди существующий зарегистрированный локальный интерфейс или UI; не выдумывай вызовы. Сохранённый документ не содержит несохранённых правок открытого окна. Не закрывай/не перезаписывай чужую работу.

## Подготовка сцен

Для каждого вида заведи имя и реестр: модель/редакция, сцена, камера, направление, теги/видимость, активное сечение, стиль, масштаб на листе и назначение.

Пример соглашения: `INT_R01_PLAN_FURN`, `INT_R01_WALL_A`, `FUR_F01_FRONT`, `FUR_F01_SEC_AA`. Это проектная конвенция, не нормативное обозначение.

Сохраняй камеры, видимость, стиль и активные сечения в нужных свойствах сцен. После сохранения уйди/вернись и проверь состояние. Номер сцены может измениться при перестановке: сопоставляй имя и индекс заново. Технические планы — ортографические; для развёртки камера направлена перпендикулярно стене. Активное сечение одного контекста не обязательно режет весь вложенный интерьер.

## Документы и шаблоны

Создай два `.layout`, используя подтверждённые шаблоны проекта. Для нового шаблона по спецификации проверь реальный файл в LayOut; Markdown/CSV не являются native-шаблоном. Поля шаблона в [template-specification.md](../assets/template-specification.md).

Формат выбирай по читаемости/печати. A3 landscape 420×297 mm — удобный старт для интерьера, A3/A4 для мебели — варианты, не обязательные нормативные назначения. Текст/размеры должны быть читаемы при печати на выбранном формате.

Слои: рамка/общие реквизиты; виды модели; штриховки/2D детали; размеры; выноски; таблицы; изменения; служебные непечатаемые элементы. Это конвенция: проверь реально поддерживаемую видимость/печать и общие слои. Заблокируй завершённую рамку и виды, не блокируя их обновление через предусмотренный механизм.

## Viewport

Вставь сохранённый SKP, выбери именованную сцену, ортографическую камеру и масштаб. При изменении bounding box проверь Preserve Scale/сохранение масштаба в установленной версии: рамка и масштаб — разные параметры. Кадрирование/маска не должны скрывать нужные детали.

Проверь overrides камеры, тегов и стилей. Не возвращай все overrides в исходное состояние вслепую: часть могла быть осознанно настроена для листа. Запиши отклонения от сцены, которые необходимо сохранить.

Режим рендера выбирай по данным: Vector для линий, Raster для пиксельной подачи, Hybrid когда нужен смешанный результат. Не назначай один режим всему альбому по умолчанию. Проверь заливки, скрытые линии, текстуры, прозрачность и сложность конкретного вида. Для работы и экспорта могут быть разные настройки качества; окончательный PDF проверяется отдельно.

Наложенные viewport допустимы, когда дают нужную графику; они требуют одинакового положения/камеры/масштаба и контроля после каждого обновления. 2D маска не должна создавать видимость отсутствующей детали.

## Аннотации и 2D детали

Размеры/выноски ставь на слой страницы, проверяя привязку к нужному viewport. Узел, выполненный 2D средствами LayOut, имеет свой масштаб в scaled group. Viewport SketchUp не включается в такую группу; для наложения держи его отдельно и контролируй масштаб обеих частей.

Не масштабируй готовые размеры/текст вместе с чертежом как изображение. Scrapbooks сохраняют повторяемую графику/таблицы; они не гарантируют актуальную нормативную форму. Создай библиотеку только из проверенных элементов без реальных клиентских сведений.

## Обновление

Сохрани исходные SKP/таблицы, обнови их references, отрендерь изменённые виды; затем проверь размеры/выноски, clipping, overrides, таблицы, поля штампа и cross-reference. Смена структуры модели/замена экземпляров может разрушить ассоциации даже при внешне похожем виде.

После крупной правки контролируй экспорт обоих альбомов: например, изменение кухни затрагивает интерьерный план/развёртку и мебельные виды/спецификацию. Сохраняй независимые номера редакций и карту соответствия.
