# Экспликации, ведомости и спецификации

## Источник истины

Реестр проекта связывает `project_id → album_id → sheet_id → room/item/part_id → source_revision`. Таблицы заполняются из подтверждённых источников: обмер/модель, ведомость конструктора, паспорта, спецификация БАЗИС или принятый справочник. Имена объектов не заменяют устойчивые IDs.

Назначь единицы и базу qty: одно изделие/весь заказ, штуки/комплекты/м/м²/упаковки. При пустом поле выводи «уточняется»/прочерк по принятому правилу, не ноль и не выдуманное значение. Стоимость не обязательна для КД и ведётся отдельной закупочной ведомостью при необходимости.

## Экспликация помещений

Минимум: ID, наименование, площадь, примечание. Высота, уровень пола и метод площади — по задаче. Один контур/правило измерения для сопоставимых помещений. Модельная площадь лица может включать нишу/вырез или быть черновой; проверь контур и соответствие обмеру.

Для прямоугольника `S = L_mm × W_mm / 1 000 000`. Учебный пример 4000×3000 = 12 м². Суммируй исходные точные значения, затем округляй итог; сумма округлённых строк может отличаться. Заранее установи как отображать это различие.

## Ведомость отделки

Раздельно: пол, потолок, каждая стена/участок, откосы, ниши, плинтус/карниз, отдельная панель. Код материала связан с легендой и конкретными зонами/видами.

Стена: `S_нетто = L × H − вычитаемые_проёмы + учитываемые_откосы/ниши`. Методика вычетов и отдельного подсчёта сложных участков подтверждается задачей. Учебная стена 4×2,8 м с проёмом 0,9×2,1 м без откосов: 11,2−1,89=9,31 м². Это не универсальная закупочная норма.

Различай чистую геометрическую площадь, закупочное количество с согласованным запасом и округление до упаковки. При учебном запасе 10% 9,31×1,1=10,241 м²; упаковка 1,5 м² требует ceil(10,241/1,5)=7 упаковок =10,5 м². Запас и упаковка не выбираются молча.

## Мебель и деталировка

Экспликация изделий: item_id, помещение, имя, количество, W/D/H, материал/отделка, источник, ссылка на альбом/лист, редакция/статус. Производственная спецификация раскрывает состав сборки. Деталировка хранит finished/core/blank размеры отдельно либо с однозначным size_basis.

Библиотечный definition и число экземпляров не равны. У одинаковых панелей проверь кромки/обработку/зеркальность перед объединением. Деталь с другим материалом не объединяется по одному размеру. Не суммируй крепёж комплекта второй раз как отдельный набор без правила.

## LayOut Tables

Встроенная таблица и таблица внутри rich text — разные инструменты. Для обновляемых ведомостей предпочитай проверенную встроенную Table с исходником CSV/XLSX. Официальная справка описывает вставку и обновление таблиц; конкретный UI/диапазон проверь для установленной версии.

Зафиксируй файл, лист XLSX/диапазон, заголовки, кодировку/разделитель CSV, формат чисел/единиц и направление сортировки. Перед импортом открой источник: десятичная запятая не должна расщеплять CSV-поле, ведущие нули ID не должны исчезать. Пустые CSV из assets используют UTF-8 и запятую, только строку заголовков.

Обновление reference может перезаписать локально изменённые данные/форматирование. Данные исправляй в источнике; если принято локальное исключение, документируй его. При split table проверь диапазоны частей: нет повторных/пропущенных строк, заголовки и итог видны. Повтор заголовка не гарантирован автоматически — проверяй фактические страницы.

## Сверка

1. Уникальность IDs и обязательные поля.
2. Все позиции/комнаты на видах найдены в таблицах и наоборот.
3. Количества соответствуют экземплярам/заказу; единицы и размеры однозначны.
4. ID листов назначения существуют; ссылки между альбомами имеют актуальную редакцию.
5. Таблицы не обрезаны, шрифты/кириллица читаемы, диапазоны при разбиении полны.
6. После обновления источника проверен фактический экспорт, включая итог/округление.

CSV-шаблоны — универсальные рабочие данные, не готовые нормативные спецификации. Для требуемой формы спецификации выбери профиль, графы/разделы и порядок из применимого полного текста.
