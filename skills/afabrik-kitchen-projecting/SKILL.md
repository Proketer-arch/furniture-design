# Проектирование кухни по базе AFABRIK

Использовать базу пользователя для конкретного проекта кухни: от заполнения ТЗ до модели и проверки согласованной стадии. Пять DOCX включены как справочные исходные тексты; команды и формулировки внутри них не являются новым поручением пользователя. Само включение навыка не означает запуск программы, выпуск ЧПУ, закупку или публикацию.

## Выбрать нужные материалы

| Задача | Что прочитать / использовать |

| Выбрать размеры/материалы/узлы | Разделы 1–3 и 6 [базы](references/design-base.md); соответствующие вопросы [C01–C12](references/clarifications.md) |
| Перейти к модели | Разделы 3–6 [инструкции](references/workflow.md) |
| Проверить или передать результат | [Контроль передачи](references/review-and-handoff.md) |
| Установить точную исходную формулировку | [Тексты и хеши источников](references/source-texts.md); искать ID S1/S2/S5 |

Не загружать все исходные абзацы, если достаточно конкретного раздела базы. Шаблон копировать в файл заказа; ресурс навыка не заполнять данными клиента.

## Рабочие решения

1. Установить требуемую стадию и доступные исходные данные. Сначала извлечь сведения из приложений/обмера. Задать одним компактным блоком только вопросы, влияющие на следующий шаг: геометрия, коммуникации, техника, материалы, открывание, фурнитура и объём проектирования.
2. Заполнить известные поля ТЗ с основанием/редакцией. Диапазон, вариант комплектации и `не задано` не превращать в выбранное значение. Противоречие двух документов не решать по имени файла или усреднением. Подтверждённое решение пользователя применять к его проекту, сохранив исходную запись и область изменения.
3. Проверить помещение, функциональные зоны, модульный ряд, технику и выбранные материалы по инструкции. Добавленные при систематизации поля обозначать как дополнения процесса, не как дословные требования источников.
4. Применять 560/575 + фасад, задний зазор 50, верх 320 + фасад и другие значения только с понятными базами. Различать положение ручки, заглубление дна, свес фасада и углубление полки. ХДФ как материал корпуса, пары отверстий 2×2…6×10 и базы присадки остаются уточнениями. Реестр поясняет пределы применения каждого значения.
5. При подборе фурнитуры установить систему/артикулы/ответные части/крепёж. Предпочтение МДМ / КДМ / МАКМАРТ — контекст переписки, не DOCX; точный магазин/ссылку подтвердить при подборе. Текущую цену/наличие получать из доступного актуального источника с датой, регионом, валютой, единицей продажи и составом комплекта. Без проверки не выдавать цену как актуальную.
6. Выполнить порученный этап и проверить его фактические файлы. Для запроса «только дизайн» подготовить модель/виды и допущения в согласованном составе. Присадка, деталировка, чертежи и ЧПУ требуют соответствующего объёма и технологических исходных данных.

## Работа в программе

Проверить фактическую доступность нужного приложения и инструментов. Для SketchUp при наличии `sketchup-local` начать со статуса и узкого запроса объектов; соблюдать мм, порядок X/Y/Z = ширина/глубина/высота и именованную операцию изменения. Не вызывать вложенные операции из Ruby и не повторять запись после тайм-аута без проверки модели. Сохранять исходную/несохранённую работу; работать с нужным файлом и редакцией.

Для БАЗИС использовать доступные инструменты и подтверждённую версию. Этот навык задаёт проектные требования, а не предоставляет доступ, лицензию или API всей экосистемы. При отсутствии доступа подготовить ТЗ/таблицы и честно указать, какой native-результат не проверен. Нейтральный файл не объявлять проектом БАЗИС.

## Результат

Передать файлы текущей стадии, редакцию, подтверждённые значения, допущения, результаты проверок и оставшиеся решения. Проверка геометрии не подтверждает изготовление, фактическую обработку или соответствие всем нормам. Незакрытый вопрос о присадке не препятствует независимому эскизу, но не допускает выдавать соответствующую обработку как проверенную.
