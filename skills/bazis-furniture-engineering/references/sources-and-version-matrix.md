## 2. Карточка подтвержденной функции

`capability | task | module/service | product_build | API_version | source_URL | document_date/revision | section | license/role | local_test | status`

Статус источника: полный текст прочитан / найден в официальной индексации / документ недоступен / версия не определена. Статус локального исполнения — отдельное поле. Дата поиска не является датой документа.

Если официальный портал не открывается, попробуй документ из официального CDN либо доступную встроенную справку. Индексацию используй для обнаружения; текущие параметры, сигнатуры и цены должны быть проверены по нужному документу/установке. Не заявляй, что прочитал весь PDF, по одному сниппету.

При анализе PDF-диаграммы/скриншота проверяй визуальный вид страницы, а не только текстовое извлечение: базы и стороны могут быть показаны графически. Не копируй примерный режим со скриншота в производственную настройку.

## 3. Совместимость

Матрица: `module/version → model/library → API → database → exchange/schema → postprocessor/controller → cloud service`. Для каждого используемого ребра зафиксируй поддержку и пример readback. Не предполагается, что совпадение года у всех модулей автоматически означает одинаковые обновления и схемы.

При конфликте источников приоритет имеет относящийся к фактическому build/артикулу/оборудованию документ. Новость о старой функции может объяснить появление возможности, но не текущий контракт.

## 4. Стоимость и лицензия

Цены/условия/тарифы меняются, поэтому числовой прайс не включен в навык. Для решения о покупке проверь состав, регион, налоги, модуль, вариант ключа/лицензии, срок, обновления, постпроцессор и облачные услуги. Не выдавай одно число как цену всей экосистемы.

Не устанавливай, не мигрируй, не меняй лицензию и не покупай тариф лишь потому, что пользователь хочет подготовить проект. Сначала проверь имеющуюся возможность и подготовь конкретное решение в пределах поручения.
