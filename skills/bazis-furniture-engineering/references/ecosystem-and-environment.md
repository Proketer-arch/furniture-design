# Экосистема и паспорт среды

## 1. Карта модулей

Области работы сверены с официальным указателем руководств и описанием системы; наличие функции, редакцию и лицензию проверяй для конкретной установки.

| Модуль/сервис | Для какой части задачи | Проверяемый выход |
|---|---|---|
| БАЗИС-Мебельщик | Конструкторская модель, панели/узлы, фурнитура и документы | Модель, детали, операции, листы |
| БАЗИС-Шкаф | Параметрическое проектирование в поддерживаемом модулем диапазоне | Конфигурация и проверенная передача дальше |
| БАЗИС-Раскрой | Карты раскроя и расход материалов | Карты, панели, остатки и соответствие количеств |
| БАЗИС-ЧПУ | Передача обработок на конкретную систему станка | Управляющие файлы и карта установки |
| Постпроцессор раскроя/симулятор/нестинг | Дополнительный производственный маршрут при доступности | Файлы/проверки под конкретное оборудование |
| БАЗИС-Бирка | Маркировка деталей/пакетов в поддерживаемом маршруте | Бирки, поля и соответствие ID |
| БАЗИС-Принт | Компоновка/печать документов | Проверенные листы и фактический результат печати |
| БАЗИС-Смета | Стоимость по базе и принятой методике | Расчет с источниками/составом |
| БАЗИС-Упаковка | Состав и схемы пакетов | Пакеты, комплектность, маркировка |
| БАЗИС-Склад | Учет материалов и операций склада | Подтвержденные движения/остатки |
| БАЗИС-Салон | Каталоги/интерьеры/оформление заказа по конфигурации | Выбранное изделие, заказ и передаваемые данные |
| БАЗИС-Просмотр | Просмотр поддерживаемых документов | Проверенный доступный вид |
| Рендер | Визуальная подача при доступности | Изображение и исходная редакция |
| БАЗИС-ID/Онлайн | Учетная запись и лицензирование/доступ к модулям | Проверенные права и условия использования |
| БАЗИС-Облако | Облачные услуги, просмотр/хранение/заказы по тарифу | Файлы, права, ссылка/заказ и статус |
| БАЗИС-Расстановка/AR | Презентационный сценарий, если доступен | Проверенный вид и ограничения масштаба |
| 1С-БАЗИС/другой ERP-обмен | Связь производства и учетной системы | Сопоставленные справочники и протокол обмена |

Источники: [руководства](https://bazissoft.ru/file/guide), [описание системы](https://www.bazissoft.ru/about/about_bazis-center), [установка 2026](https://help.bazissoft.ru/tdocs/ustanovka-modulei-sistemi-bazis-2026-64-bit-bvzn2n19y12v5f8). Карта — маршрутизация задач, не утверждение, что все позиции входят в купленный комплект или управляются одним API.

## 2. Паспорт установки

`Модуль | версия/build | 32/64-bit | OS | лицензия/режим | доступная функция | база/путь | способ управления | проверено когда`

Фиксируй фактическую среду, а не только номер релиза в интернете. Для текущего macOS workspace не предполагается установленный БАЗИС: уточни/обнаружь разрешенное рабочее место Windows, удаленный доступ либо работу с файлами. Не объявляй эмуляцию, RDP, VM или облачную услугу уже настроенной.

Для готового проекта: путь/тип документа, редакция, источник, внешние библиотеки, версия материальной базы, язык/локаль, единицы и правила округления. Для API: среда выполнения, версия скриптового API, доступные методы и способ запуска.

## 3. Выбор маршрута

- Локальная правка → Мебельщик/Шкаф и затронутые документы.
- Новое семейство → параметры/библиотеки, диапазоны, тесты и документы.
- Выпуск панели на станок → обработка, ЧПУ, конкретный постпроцессор/установка, контроль.
- Партия → Раскрой, маркировка, ЧПУ/пильный маршрут, упаковка и учет по заданию.
- Клиентская комплектация → Салон/Смета с актуальным изделием и ценами.
- Просмотр клиентом → соответствующий просмотр/облачная услуга с нужными правами.
- Обмен с ERP → проверенная схема/справочники, тестовый импорт и readback.

Не выбирать весь маршрут, если пользователь просит одну стадию. Установи, что вход следующего модуля действительно включает нужные данные предыдущего.

## 4. Версии и обновления

Обновление может менять API, форматы, библиотеки и постпроцессоры. До миграции зафиксируй версии и резервные копии, совместимость ключей/БД, порядок перехода и откат. Руководство по переходу 32→64-bit не означает, что безопасно заменить все библиотеки на месте.

Не обновляй работающую production-среду ради новой команды без причины и соответствующего поручения. Сначала проверь нужную функцию в имеющейся версии, подготовь тестовую миграцию и конкретный результат для решения пользователя.

Не обещай условия лицензии/продления/стоимость по старому прайсу. Проверяй официальные условия на дату задачи, отдельно права на модуль, постпроцессор, обновления и облачные услуги.

## 5. Способ управления

Проверяй доступный connector/API/официальный скриптовый механизм, затем разрешенный интерфейс. Если инструмент отсутствует, подготовь локальные артефакты и последовательность действий без имитации исполнения. Не запускай команды Node.js вместо скриптового host БАЗИС и не используйте SketchUp Ruby как API БАЗИС.

Любая автоматизация должна иметь ограниченную область, проверенные входы, воспроизводимый пример и обратный контроль. Результат статической проверки файла не равно его успешному исполнению в установленной программе.
